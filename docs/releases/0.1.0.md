# EmbCC 0.1.0

November 2026. The second release, and the first without a pre-release
suffix: `install.sh` with no `--version` installs it.

```sh
curl -fsSL https://raw.githubusercontent.com/EmbLinkOs/EmbCC/main/install.sh | sh
```

What changed since [0.0.1-beta](https://github.com/EmbLinkOs/EmbCC/releases/tag/v0.0.1-beta)
(October 2026), in about 540 commits. The numbers are pull requests.

## A change that can break a build

**The default target is the machine EmbCC runs on**, as with GCC and
clang (#198). `embcc hello.c` on an Apple-silicon Mac now builds for
`aarch64-apple-darwin`, and on x86-64 Linux for `x86_64-linux-gnu`.
Before, it built for `x86_64-elf`. A build that relied on that names
it: `--target=x86_64-elf`, or `EMBCC_DEFAULT_TARGET=x86_64-elf` in the
environment. See [The default target](../manual/invoking.md#the-default-target).

## Code

- Code size against GCC, two rounds (#183, #196): Thumb-2 64-bit shifts
  without branches, `cmn`, `bic` and `orn` for negative and inverted
  constants, bit tests as shifts, 8-byte single-integer structs passed in
  registers on AAPCS, RV32 and Xtensa, and more.
- Xtensa: the density option's 16-bit instructions, `addx2/4/8`, and
  `beqz.n`/`bnez.n` (#185).
- `-O3` is a level of its own: loop unswitching, constant parameters
  propagated into callees, and inlining weighed by optimized size (#178).
- Performance rounds for embedded code (#165, #181): AVR interrupt
  handlers as short as avr-gcc's, invariant loads hoisted after
  unrolling, RV64 integer indices, `lr` used as a register on Thumb.
- Against clang 23 on 2026-11-08 (see the
  [scoreboard](../internals/scoreboard.md#2026-11-08)), code size per
  object at `-Os` is 1.04 on Cortex-M4, 1.10 on Cortex-M0 and 1.12 on
  RV32 (below 1.0 on Cortex-M4 without the math library), and the
  benchmark's speed is within 6% on Cortex-M4 and RV32.

## Debugging optimized code

- Lexical blocks: a variable declared in an inner block or a `for`
  clause is shown only there, so sibling loops' `i` are told apart (#197).
- Inlined calls appear as frames of their own in `bt`, with the
  variables of the inlined function (#197).
- A new test steps through a program in GDB on four QEMU boards
  (Cortex-M3, Cortex-M0, RV32, MIPS) at `-O0`, `-O2` and `-Os`, and
  checks every value GDB shows against clang `-O0` (#197).
- `.debug_frame` on AVR, and `embdbg` unwinds by `.debug_frame` on every
  target that has it (#185).

## Languages

- C23 features, GNU vector types, integer `_Complex`, `asm goto`, and
  the gaps to GCC and clang listed in #163 and #171.
- `_Thread_local` with local-exec TLS on ARM and RISC-V; `_Atomic`
  floats and structs with GCC's layout (#185).
- Inline asm: outputs wider than a register, ARM's `%Q`/`%R`/`%H`, the
  RISC-V `"f"` constraint; callee-saved clobbers saved on every backend
  (#185).

## Targets, boards and tools

- `riscv32-none-elf` and `riscv64-none-elf` (#147).
- `--board=uno`, `nano`, `mega2560` and `esp32-devkit` (#177).
- EmbSim: ESP32-C3, Arduino Zero (#144) and a Cortex-M23 (#185).
- `embflash`: Arduino boards through their STK500 bootloaders (#172,
  #177), and ESP32 flash write and read-back (#176).
- `embld`: Xtensa images laid out from linker scripts (#174).
- Assemblers: NASM syntax, 16- and 32-bit x86, Arm MVE and NEON,
  AVX-512, TriCore, and `PHDRS` in linker scripts (#179, #180).
- The C library: POSIX threads, semaphores, regex, glob, `iconv`, the
  resolver API and more (#162, #166-#169).

## Fixes

Wrong code, all with tests:

- 16-byte atomic nand on x86-64 (#154).
- A Win64 `va_arg` (#175).
- A 64-bit widening of a parameter that lost its high word (#185).
- Crashes and slow compiles that GCC's torture suite found (#159).

## Testing

- CI builds and tests every pull request: GCC and clang on Linux and
  macOS, the whole test suite on QEMU in four parts, 150 fuzz seeds, and
  EmbCC compiling itself (#152, #182).
- Every night, GCC's torture suite, and 200 new fuzz programs on x86-64
  and four QEMU boards (#157).
